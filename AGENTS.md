# Repository Guidelines

## Scope

This repo configures a two-hop proxy. `edge/` is the x-ui panel host (inside a restricted country),
`exit/` is the Turkish exit VM, `shared/` is the material both sides must agree on.

## Hard rules

- **Never commit plaintext secrets.** The REALITY private key, public key and client UUID live only
  in `shared/vault.yml` (ansible-vault). `shared/vault.yml.example` documents the shape.
- **Never duplicate a cross-side value.** If both ends need it, it belongs in `shared/endpoints.yml`
  and is read from there. Duplication is how the tunnel breaks silently.
- **Never hand-edit `edge/.env`.** It is generated by `make edge-render`; it is gitignored.
- **Validate before applying.** `edge/scripts/apply-xray-template.sh` runs `jq -e` and
  `xray -test` and snapshots the panel DB before writing. Keep it that way.
- **Infra changes are applied by a human.** CI lints and syntax-checks; it never deploys.

## Conventions

- Shell: `#!/usr/bin/env bash`, `set -euo pipefail`, paths resolved relative to the script.
- Ansible: fully-qualified module names (`ansible.builtin.*`), roles idempotent, every service
  restart gated behind a config validation handler.
- YAML two-space indent; JSON formatted with `jq`.
- Commit subjects: short, lowercase, scoped — `feat(edge): ...`, `feat(exit): ...`, `docs: ...`,
  `chore: rotate reality keypair`.

## Before submitting

```bash
make lint      # jq + xray -test + ansible-lint + cross-side consistency
make doctor    # no REPLACE_ME left behind
```

After each change, suggest the commit message to use.
